Domain: Student Information System (SIS)

The domain for this assignment is the Student Information System (SIS) introduced in Lecture 6. It models the entities and relationships of a university setting: users (students, professors, teaching assistants), courses, enrollments, and grades.

You are expected to build on and significantly extend the SIS introduced in the lecture. The table below shows the core entities your implementation must include.

Required Classes 10P

User Hierarchy 6P

Abstract Class User

User is the abstract base class for all persons in the SIS. It must:

  • Be defined using abc.ABC: instantiating it directly must raise a TypeError
  • Store the following attributes: id (int), name (str), email (str), birth_date (str), birth_place (str)
  • Declare at least one abstract method that all subclasses must implement (e.g., get_email_signature() -> str)
  • Declare at least one abstract property (e.g., role) that returns a string describing the type of user
  • Implement __repr__ using the attributes available at this level

Class Student

Student inherits from User and adds:

  • matriculation_id (int) and program (str)
  • Concrete implementations of get_email_signature() and role
  • At least one attribute managed via @property with a setter that validates input
  • An info() method that prints all relevant attributes

Class Professor

Professor inherits from User and adds:

  • department (str) and office (str)
  • Concrete implementations of get_email_signature() and role
  • An info() method that prints all relevant attributes

Class TeachingAssistant

TeachingAssistant must use multiple inheritance, inheriting from both Student and Professor. It represents a student who also assists in teaching a course. Requirements:

  • Correctly resolves the MRO: you must be aware of which parent's __init__ and methods are invoked and in what order
  • Adds a supervised_course attribute (a Course object) indicating which course the TA is assisting
  • Overrides get_email_signature() to reflect the dual role
  • Overrides role to return "Teaching Assistant"
Note: Python's MRO follows the C3 linearization algorithm. You are expected to understand the resolution order for TeachingAssistant and explain it briefly in your report.

Dataclass Course

Course must be implemented as a dataclass with the following fields: code (str), name (str), ects (int), lang (str). It must also provide an info() method that returns a formatted string.

Class Grade

Grade represents a single graded assessment within an enrollment. It must store: type (str, e.g. "Midterm"), value (float), date (date), retry (int). The magic methods it must implement are described in the Magic Methods section.

Class Enrollment

Enrollment links a student to a course and owns its grades. It must:

  • Use aggregation for student and course : both are created outside and passed in
  • Use composition for the list of Grade objects : grades are created inside Enrollment and never exist independently
  • Store the semester (str) in which the enrollment takes place
  • Define a class attribute total_enrollments (int) that tracks how many Enrollment instances have been created across the entire program
  • Define a class method enrollment_summary() that returns a string reporting the total number of enrollments
  • Implement the magic methods described in the Magic Methods section

Mixins

You must implement the following two mixins:

  • ComparableMixin: provides comparison behavior (__lt__, __le__, __eq__) based on a single key attribute. The mixin must be general: each class that uses it declares a _compare_key class attribute (a string naming the attribute to compare on), and the mixin reads it dynamically using getattr. Apply it to at least one class in your hierarchy (e.g., Student comparing by name). The payoff is that sorted() and min()/max() work on any object with the mixin applied, with no extra arguments needed.
  • ExportableMixin: provides a to_dict() method that returns a dictionary of the object's attributes. Apply it to at least one class (e.g., Course or Grade).
Note: A mixin should not store state in its own __init__. It provides behavior only, relying on attributes defined by the class it is mixed into. Explain this design choice in your report.

Class GradeEvaluator 3P

Implement a class GradeEvaluator that acts as a callable object. It encapsulates a passing threshold and can be applied to a list of enrollments to identify passing students.

  • __init__(self, threshold: float, passing_label: str = "Pass") : stores the threshold and label
  • __call__(self, enrollments: list[Enrollment]) -> list[Student] : returns the students whose average grade across all their enrollments meets the threshold
  • __repr__(self) : returns a string such as GradeEvaluator(threshold=4.0, passing_label='Pass')
Note: Using __call__ makes GradeEvaluator behave like a function: evaluator(enrollments): while still being stateful and configurable. This is something a plain function cannot provide. Discuss this design choice in your report.

Semester Simulation 5P

Once your classes are implemented, write a script (e.g., simulation.py) that simulates a full university semester using the SIS. The simulation must demonstrate that all your classes work together correctly.

The simulation must perform the following steps, in order:

  1. Setup: create at least 3 students, 2 professors, 1 teaching assistant, and 3 courses
  2. Enrollment: enroll each student in at least 2 courses; assign the teaching assistant to one of them
  3. Grading: add at least 2 grades per enrollment using the << operator
  4. Querying: use Enrollment.__call__ to retrieve grades above a given threshold for at least one enrollment
  5. Evaluation: use GradeEvaluator to determine which students are passing across all their enrollments
  6. Export: use ExportableMixin.to_dict() to print a dictionary summary of at least one course and one grade
  7. Comparison: demonstrate ComparableMixin by calling sorted() on a plain list of students (no custom key argument) and printing the result in order. Then do the same for a list of grades. The point is that sorted() works transparently on any object that has the mixin applied, without the caller knowing anything about the comparison logic.

The simulation output must be readable in the console. Print a short label before each step so the output is easy to follow.
